This guide builds cpo3 from source and solves a small quadratic program.
Choose Python or Rust below; both examples solve the same problem.

## The example problem

We minimize a quadratic objective subject to two upper bounds:

$$
\begin{aligned}
\underset{x_1,x_2}{\operatorname{minimize}}\quad
& \tfrac12(x_1^2+x_2^2)-x_1-2x_2 \\
\text{subject to}\quad & x_1\leq 0.5, \\
& x_2\leq 4.
\end{aligned}
$$

The unconstrained minimizer is $(1,2)$, so the first bound changes the solution
to $x=(0.5,2)$, with objective value $-2.375$. The first constraint is active;
the second has slack. We will check the primal solution, slacks, and multipliers.

## Install and solve

cpo3 is not yet published on PyPI or crates.io. Install it from source using
the instructions below.

<Tabs>
<TabItem label="Python">

### Install

You need:

- [Rust 1.91 or later](https://www.rust-lang.org/tools/install), to build the solver.
- Python 3.10 or later.
- [uv](https://docs.astral.sh/uv/getting-started/installation/), to manage the Python environment.
- Git, to clone the source.

Clone the solver repository and install the package and its dependencies:

```sh
git clone https://github.com/cpo3-org/cpo3.git
cd cpo3
uv sync
```

### Solve

Save this as `example.py` in the solver checkout:

```python title="example.py"
import cpo3
import numpy as np
from scipy import sparse

problem = cpo3.Problem(
    P=sparse.eye(2, format="csc"),
    c=np.array([-1.0, -2.0]),
    A=sparse.eye(2, format="csc"),
    b=np.array([0.5, 4.0]),
    cones=[cpo3.NonnegativeCone(2)],
)

solution = cpo3.solve(problem)
print(solution.status)

if solution.status == cpo3.SolverStatus.SOLVED:
    print(solution.x)
    print(solution.y)
    print(solution.s)
    print(solution.info.pobj)
```

Run it using the environment created by `uv sync`:

```sh
uv run python example.py
```

The result should be approximately:

```text
SolverStatus.SOLVED
[0.5 2. ]
[0.5 0. ]
[0. 2.]
-2.375
```

The solver returns floating-point approximations, so the last few digits may
differ. Use `uv run python` for your other scripts in this checkout as well.

### Set options

Pass a `Settings` object to change the defaults. For example, print progress
and set a time limit of 30 seconds:

```python
settings = cpo3.Settings(verbose=True, time_limit=30.0)
solution = cpo3.solve(problem, settings=settings)
```

### Install

You need [Rust 1.91 or later](https://www.rust-lang.org/tools/install) and Git.
Create a Rust application:

```sh
cargo new cpo3-example
cd cpo3-example
```

Add cpo3 under the existing `[dependencies]` heading in `Cargo.toml`:

```toml title="Cargo.toml"
[dependencies]
cpo3 = { git = "https://github.com/cpo3-org/cpo3.git" }
```

### Solve

Replace `src/main.rs` with:

```rust title="src/main.rs"
use cpo3::{Cone, CscMatrix, Problem, Settings, SolverStatus, solve};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let problem = Problem::new(
        Some(CscMatrix::identity(2)?),
        vec![-1.0, -2.0],
        CscMatrix::identity(2)?,
        vec![0.5, 4.0],
        vec![Cone::Nonnegative(2)],
    )?;

    let solution = solve(&problem, &Settings::default())?;
    println!("{:?}", solution.status());

    if solution.status() == SolverStatus::Solved {
        println!("{:?}", solution.x());
        println!("{:?}", solution.y());
        println!("{:?}", solution.s());
        println!("{}", solution.info().pobj);
    }
    Ok(())
}
```

Build and run in release mode for numerical workloads:

```sh
cargo run --release
```

After compilation, the result should be approximately:

```text
Solved
[0.5, 2.0]
[0.5, 0.0]
[0.0, 2.0]
-2.375
```

The solver returns floating-point approximations, so the last few digits may
differ.

### Set options

Use struct update syntax to change selected defaults. Replace the call to
`solve` above with:

```rust
let settings = Settings {
    verbose: true,
    time_limit: Some(std::time::Duration::from_secs(30)),
    ..Settings::default()
};
let solution = solve(&problem, &settings)?;
```

## How the data describes the problem

cpo3 represents the objective as $\tfrac12 x^\mathsf{T}Px+c^\mathsf{T}x$
and the constraints as $Ax+s=b$, where $s$ belongs to the specified cones.
For this example:

| Input | Value | Meaning |
| --- | --- | --- |
| `P` | Identity matrix | The quadratic term is $\tfrac12(x_1^2+x_2^2)$. |
| `c` | `[-1, -2]` | The linear term is $-x_1-2x_2$. |
| `A` | Identity matrix | One constraint row for each variable. |
| `b` | `[0.5, 4]` | The two upper bounds. |
| `cones` | One nonnegative block of dimension 2 | $s\geq0$, so $Ax\leq b$. |

Cone blocks describe consecutive rows of `A` and `b`; their dimensions must sum
to the number of constraints. A zero-cone block enforces equality on its rows.
Variables have no implicit nonnegativity restriction: express lower bounds as
additional inequality rows.

For a linear program, set `P=None` in Python or pass `None` for the first
argument to `Problem::new` in Rust. See the [problem-data reference](/reference/#problem-data)
for dimensions and input conventions.

## Check the result

Check for `SOLVED` in Python or `Solved` in Rust before interpreting the vectors
as an optimal solution. The solver may instead return an infeasibility
certificate or stop at an iteration or time limit.

For a solved problem, `x` contains the primal variables, `y` the dual
multipliers, and `s` the constraint slacks, all in the original problem units.
Here the values should be approximately

$$
x=\begin{pmatrix}0.5\\2\end{pmatrix},\qquad
y=\begin{pmatrix}0.5\\0\end{pmatrix},\qquad
s=\begin{pmatrix}0\\2\end{pmatrix}.
$$

The first bound is active: $x_1=0.5$ and $s_1=0$. Its positive multiplier
$y_1=0.5$ indicates that relaxing this bound would decrease the optimal
objective, locally at a rate of $0.5$ per unit. The second bound is inactive:
$s_2=2$ and $y_2=0$.

These values satisfy primal feasibility $Ax+s=b$, stationarity
$Px+c+A^\mathsf{T}y=0$, and complementarity $s_i y_i=0$.
Small residuals, near-zero values, and signed zeros are normal in numerical output.

The `info` object reports objective values, residual norms, elapsed time, and
iteration counts. This small example can be solved entirely during presolve,
so `info.iters` may be zero. For an interior-point run, set `presolve=False` in
Python or `presolve: false` in Rust.

See [solution fields](/reference/#solutions-and-diagnostics) and
[termination statuses](/reference/#termination-statuses) for the full interpretation.
